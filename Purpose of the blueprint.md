Purpose of the blueprint.md file

The blueprint.md file serves as the single source of truth for the entire project.

In my own words, its purpose is threefold:

It's the project's memory. It contains a complete and continuously updated history of the website, documenting every feature, design choice, and structural change that has ever been implemented. This ensures that I have the full historical context and don't "forget" what has been done in previous sessions.

It's the official description of the current application. It provides a detailed outline of the project in its present state—its purpose, capabilities, style, and features. When I read it, I get a definitive snapshot of how the application is supposed to look and function right now.

It's my immediate to-do list. For any new task that you give me, it holds the specific plan of action, including an overview and a list of steps that I must follow to complete the request.

Essentially, by reading the blueprint.md file at the start of every session, I am supposed to know exactly what the project is, how it got here, and what I need to do next. It is the most critical document for me to avoid confusion, prevent errors, and work effectively.
